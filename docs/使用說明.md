# Lost and Found AI 使用說明

本專案是提供遺失物系統呼叫的 AI 圖片特徵擷取服務。服務使用 **FastAPI** 提供 HTTP API，並以 **DINOv2** 將圖片轉換成固定長度的特徵向量（Embedding），供其他系統後續儲存、檢索及計算圖片相似度。

> 目前版本提供圖片檢查及特徵向量產生功能；尚未包含向量資料庫、相似圖片搜尋、自然語言搜尋、使用者登入或遺失物資料管理。

## 1. 功能一覽

| 功能 | API | 說明 |
| --- | --- | --- |
| 服務狀態 | `GET /` | 確認服務是否正常啟動 |
| 健康檢查 | `GET /health` | 回傳服務健康狀態 |
| 圖片檢查 | `POST /api/v1/images/inspect` | 驗證圖片並取得檔名、格式、寬度及高度 |
| 圖片特徵擷取 | `POST /api/v1/images/embedding` | 使用 DINOv2 將圖片轉成特徵向量 |

支援的圖片格式：JPEG、PNG、WebP。上傳時使用 multipart/form-data，欄位名稱為 `file`。

## 2. 環境需求

- Python 3.10 以上（建議使用與目前 PyTorch、Transformers 套件相容的版本）
- 網路連線：第一次啟動時需要從 Hugging Face 下載模型及影像處理器
- CPU 可以執行；有 NVIDIA GPU 與相容的 CUDA/PyTorch 環境時會優先使用 GPU

### 安裝套件

在專案根目錄執行：

```bash
python -m venv .venv
```

啟用虛擬環境：

```bash
# Windows PowerShell
.venv\\Scripts\\Activate.ps1

# macOS / Linux
source .venv/bin/activate
```

安裝專案目前列出的套件，以及程式實際需要的 PyTorch 和 Transformers：

```bash
pip install -r requirements.txt
pip install torch transformers
```

**依賴提醒：** 目前 `requirements.txt` 尚未列出 `torch` 與 `transformers`，但 DINOv2 模型程式會直接匯入這兩個套件。因此首次安裝時必須額外安裝。若要使用 NVIDIA GPU，請依照 PyTorch 官方安裝頁面選擇符合主機 CUDA 環境的安裝指令，不要直接假設一般的 `pip install torch` 一定會安裝 GPU 版本。

## 3. 啟動服務

在專案根目錄執行：

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8080
```

服務啟動時會自動載入 DINOv2 模型。第一次啟動可能需要等待模型下載及載入完成；模型尚未載入完成前，API 不應視為已可提供推論服務。

啟動後可使用：

- API 根路徑：`http://localhost:8080/`
- 健康檢查：`http://localhost:8080/health`
- Swagger API 文件：`http://localhost:8080/docs`
- ReDoc API 文件：`http://localhost:8080/redoc`

若服務執行在雲端主機，請將 `localhost` 換成該服務可被呼叫的主機位址或內部服務位址。

## 4. API 使用方式

### 4.1 確認服務啟動

請求：

```http
GET /
```

成功回應範例：

```json
{
  "message": "Lost and Found AI Service is running",
  "version": "0.1.0"
}
```

### 4.2 健康檢查

請求：

```http
GET /health
```

成功回應範例：

```json
{
  "status": "healthy"
}
```

此端點目前只回報服務健康狀態，並不會額外檢查模型是否已載入或 GPU 是否可用。

### 4.3 檢查圖片

請求：

```http
POST /api/v1/images/inspect
Content-Type: multipart/form-data
```

欄位：

| 欄位 | 類型 | 必填 | 說明 |
| --- | --- | --- | --- |
| `file` | File | 是 | JPEG、PNG 或 WebP 圖片 |

使用 cURL：

```bash
curl -X POST "http://localhost:8080/api/v1/images/inspect" \\
  -F "file=@./sample.jpg"
```

成功回應範例：

```json
{
  "filename": "sample.jpg",
  "format": "JPEG",
  "width": 1200,
  "height": 800,
  "status": "success"
}
```

這個 API 只負責讀取及驗證圖片，不會產生特徵向量，也不會保存圖片。

### 4.4 產生圖片特徵向量

請求：

```http
POST /api/v1/images/embedding
Content-Type: multipart/form-data
```

欄位：

| 欄位 | 類型 | 必填 | 說明 |
| --- | --- | --- | --- |
| `file` | File | 是 | JPEG、PNG 或 WebP 圖片 |

使用 cURL：

```bash
curl -X POST "http://localhost:8080/api/v1/images/embedding" \\
  -F "file=@./sample.jpg"
```

成功回應欄位：

| 欄位 | 說明 |
| --- | --- |
| `status` | 執行結果 |
| `filename` | 原始檔名 |
| `model` | Hugging Face 模型識別名稱 |
| `model_version` | 專案設定使用的模型版本代號 |
| `embedding_dimension` | 特徵向量長度 |
| `embedding` | 由浮點數組成的特徵向量陣列 |

目前預設使用 `facebook/dinov2-base`（專案代號 `dinov2_vitb14`），特徵向量長度為 **768**。程式使用圖片的 CLS Token 作為整張圖片的特徵，並進行 L2 正規化。

回應結構示意（以下數值僅為格式示意，非實際模型輸出）：

```json
{
  "status": "success",
  "filename": "sample.jpg",
  "model": "facebook/dinov2-base",
  "model_version": "dinov2_vitb14",
  "embedding_dimension": 768,
  "embedding": [0.0123, -0.0456, 0.0789]
}
```

實際的 `embedding` 陣列會包含 768 個浮點數，文件中的示意陣列為了易讀而省略其餘數值。

## 5. 模型設定

可透過環境變數調整模型：

| 環境變數 | 預設值 | 說明 |
| --- | --- | --- |
| `MODEL_NAME` | `dinov2` | 模型家族設定值；目前模型載入流程主要依據 `MODEL_VERSION` |
| `MODEL_VERSION` | `dinov2_vitb14` | DINOv2 模型版本 |
| `EMBEDDING_DIMENSION` | `768` | 設定中的向量維度；實際回傳維度由模型設定取得 |
| `DEVICE` | `auto` | 運算裝置；`auto` 會在 CUDA 可用時選擇 GPU，否則使用 CPU |

目前程式支援的模型代號：

| 模型代號 | Hugging Face 模型 | 特徵維度 |
| --- | --- | ---: |
| `dinov2_vits14` | `facebook/dinov2-small` | 384 |
| `dinov2_vitb14` | `facebook/dinov2-base` | 768 |
| `dinov2_vitl14` | `facebook/dinov2-large` | 1024 |
| `dinov2_vitg14` | `facebook/dinov2-giant` | 1536 |

例如，在 Linux / macOS 設定使用 CPU：

```bash
export DEVICE=cpu
export MODEL_VERSION=dinov2_vitb14
uvicorn app.main:app --host 0.0.0.0 --port 8080
```

Windows PowerShell：

```powershell
$env:DEVICE="cpu"
$env:MODEL_VERSION="dinov2_vitb14"
uvicorn app.main:app --host 0.0.0.0 --port 8080
```

請注意：切換模型版本會改變向量維度。若之後將向量寫入資料庫，應確保同一個向量欄位中的資料使用相同模型版本及維度；更換模型後，舊向量通常需要重新產生，不能直接混用。

## 6. 錯誤回應與排查

| HTTP 狀態碼 | 常見原因 | 處理方式 |
| --- | --- | --- |
| `400` | 圖片格式不支援、檔案為空或內容不是有效圖片 | 確認檔案為 JPEG、PNG 或 WebP，並確認檔案內容正常 |
| `422` | 沒有提供必填的 `file` 欄位 | 使用 multipart/form-data，欄位名稱設為 `file` |
| `503` | 模型尚未成功載入或推論服務不可用 | 查看服務啟動紀錄，確認模型下載及載入成功後再呼叫 |
| 連線失敗 | 服務未啟動、網址或連接埠錯誤 | 確認 Uvicorn 正在執行，並檢查主機與連接埠 |

如果啟動時出現 `ModuleNotFoundError: No module named 'torch'` 或 `transformers`，請依照第 2 節補裝缺少的套件。

## 7. 與遺失物主系統的整合方式

建議由主系統後端呼叫本 AI Service，而不是讓瀏覽器直接呼叫模型服務：

1. 使用者在主系統上傳遺失物或拾獲物照片。
2. 主系統後端將圖片以 multipart/form-data 傳送至 `POST /api/v1/images/embedding`。
3. AI Service 回傳模型資訊及圖片特徵向量。
4. 主系統後端負責將向量與遺失物資料建立關聯並保存。
5. 使用者查詢時，由主系統後端取得待比對圖片的向量，再透過向量相似度及其他條件進行檢索。

**責任邊界：** AI Service 負責圖片特徵擷取；主系統後端負責資料保存、權限、搜尋流程及相似度比對。這樣未來更換模型或將 AI Service 部署到其他運算平台時，主系統不必大幅改動。

## 8. 目前版本的限制與正式部署注意事項

- 目前不會保存上傳圖片或特徵向量；API 回傳向量後，呼叫端必須自行保存。
- 目前沒有向量資料庫及相似度搜尋 API。
- 目前沒有自然語言搜尋或文字與圖片跨模態檢索功能。DINOv2 在此專案中負責圖片特徵擷取，不是文字圖片多模態模型。
- 目前沒有使用者驗證、API Key、速率限制或上傳檔案大小限制。正式環境應由內部網路、API 閘道或其他存取控制保護，不應直接將未受保護的服務公開給所有人。
- `/health` 目前不代表模型推論一定可用；正式監控可再增加模型載入狀態及 GPU 狀態檢查。
- 大型模型可能需要較多記憶體及 GPU 資源；若使用 CPU 或較小規格主機，請先以實際圖片測試推論速度與記憶體用量。
